# AI × Q 编辑室

与现有 GitHub Pages / Jekyll 网站配套的内容管理和阅读统计服务。界面为中文，内容支持日文与英文；黑白、细线和留白与公开网站一致。

## 已实现

- 研究笔记、知识点、活动、成员的新增、编辑与归档。
- 日英正文分别编辑、Markdown 工具栏、阅读预览、已有 HTML / Liquid 模板保留。
- 图片及 PDF 上传（单个 10 MB），保存为待发布附件。
- 持久化草稿、版本冲突检测、撤回草稿、离开页面提醒、Ctrl/Cmd + S 保存。
- 发布清单、Git 单次提交、非强制推送、失败时保留草稿、操作记录。
- 访问量、访客数、有效阅读、回访比例、每日趋势、热门页面、来源、设备、语言、CSV 导出。
- 密码登录、8 小时会话、HttpOnly / SameSite Cookie、CSRF 校验、登录限流、服务端预览清理。

所有既有正文和英文内容保持原样。活动与成员迁移到 `_data/events.json`、`_data/members.json`，首页和活动页共用模板。首页仍只展示三条过去记录。

## 本地运行

需要 Node.js 24 或更新版本（使用内置 SQLite）及 Git。

```bash
cd management
npm ci
npm run setup
npm start
```

在终端设定至少 12 位的密码，打开 `http://127.0.0.1:4321/`。默认只监听本机。不要把密码或 GitHub 令牌写入仓库。

本地编辑默认只保存草稿，发布连接为关闭状态。草稿和统计保存在 `management/.admin-data/`，重启后保留；该目录已被 Git 忽略，也被 Jekyll 排除。

## 正式部署

GitHub Pages 无法运行 Node 服务，需要另有支持 Node.js 24、持久化磁盘、HTTPS 的主机。此版本可以放在现有 VPS 或提供持久化磁盘的容器服务；不能直接作为无持久磁盘的 serverless 函数部署。

1. 在服务器准备这个仓库的专用发布副本，切换 `main`，保持干净且同步。让服务器 Git 使用仓库专用的写入凭据。不要让此副本承载其他开发工作。
2. 安装 `management` 的锁定依赖；设置下列环境变量。密码使用主机的 secret 配置功能；也可在持久磁盘通过 `npm run setup` 设置加盐哈希。
3. 通过 HTTPS 反向代理转发到 Node。反向代理保留 Host；`PUBLIC_URL` 必须与浏览器访问后台的域名完全一致。
4. 把 `ADMIN_DATA_DIR` 放在持久化磁盘。定期备份该目录及 Git 仓库；部署新代码时不要替换它。
5. 验证登录、编辑、发布和 GitHub Pages 构建后，再开启统计接收地址。

| 环境变量 | 作用 | 默认 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 从主机 secret 注入登录密码；启动时转为内存中的加盐哈希 | 未设置，使用本地 account.json |
| `PUBLIC_URL` | 后台外部 HTTPS 地址；用于来源检查及 Secure Cookie | 空，本地 HTTP |
| `REPO_DIR` | 专用 Git 仓库的绝对路径 | 本项目根目录 |
| `ADMIN_DATA_DIR` | SQLite、账号哈希和上传文件的持久化目录 | management/.admin-data |
| `ADMIN_PUBLISH` | 设置 `git` 后允许发布到 GitHub main | 关闭 |
| `SITE_ORIGIN` | 允许发送统计的公开网站源 | https://xuehaisheng.github.io |
| `PORT` | Node 监听端口 | 4321 |
| `ADMIN_HOST` | 监听地址；由反向代理部署时按主机要求设置 | 127.0.0.1 |

发布流程：核对原始内容哈希 → 拒绝未提交/过期的发布副本 → 创建独立临时 worktree → 写入清单中的内容和附件 → 生成一个提交 → 非强制推送 main → 清除已发布草稿 → 更新发布副本。推送冲突、凭据失效或网络错误时草稿保留。GitHub Pages 的构建由 GitHub 完成，后台只确认推送，界面提供构建状态链接。

如需修改部署方式或连接 GitHub OAuth，可以在现有内容 API 上扩展；当前版本采用单管理员密码和服务器 Git 凭据，不把令牌放入浏览器。

## 开始统计

后台部署成功后，在 `_data/analytics.json` 填写真实的 HTTPS 接收地址，例如把 `endpoint` 设为后台域名加 `/api/collect`，随后提交并触发 Pages 构建。空字符串时，公开网站完全不会加载追踪脚本。

- **访问量**：每个页面实例一次，按事件 ID 去重。失败后重试不会重复增加。
- **访客数**：浏览器随机标识去重，标识 30 天过期。换设备、清除存储或禁用存储会影响结果，因此不是精确人数。
- **会话**：标签页中的会话标识，页面打开时距上次活跃超过 30 分钟则创建新会话。
- **有效阅读**：仅研究笔记详情，页面前台活跃至少 30 秒，且至少读到正文的 50%。后台或隐藏标签页不累计活跃时间。
- **回访比例**：所选时间内有两个及以上会话的访客 / 所选时间内访客数。这是区间回访指标，尚不提供按首访日期划分的留存 cohort。
- **活跃时间**：标签页可见时的累计时长，单页最高 1 小时。页面末次上报丢失时可能低估。
- **来源**：只保留来源域名，不保存路径、查询参数或完整来源 URL。
- **设备与语言**：设备仅分手机、平板、电脑；语言取页面的日文/英文设置。
- **时间**：按日本时间聚合，提供 7 / 30 / 90 天范围，原始统计保留 180 天。

遵循 Do Not Track / Global Privacy Control。不保存 IP、完整 User-Agent、URL 查询参数；IP 只用于内存中短期限流。过滤常见爬虫标识；任何公开的浏览器统计都可能受到拦截、伪造和脚本失败影响，不能作为严格审计数据。统计从接入后开始，不能恢复过去访问。

建议在网站的隐私说明中写明这些收集项目、保留时长和站长联系方式，再启用公开收集。

## 备份与恢复

- 后台“连接与设置 / 下载草稿备份”导出可阅读的 JSON 草稿快照。此文件不包含账号哈希、统计和附件。
- 完整备份：停止服务后复制整个 `ADMIN_DATA_DIR`（包括 SQLite、账号和 media 目录），或使用 SQLite 自带备份功能获得一致性快照。只复制运行中的主 `.sqlite` 文件可能遗漏 WAL 中的数据。
- 恢复：停止服务，把完整备份恢复到同一路径，确认文件权限后启动。
- 公开内容的历史可通过 Git 提交恢复。建议先在分支核对，再通过正常发布流程恢复。
